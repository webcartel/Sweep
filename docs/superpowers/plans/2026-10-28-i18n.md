# Multilingual Interface (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every user-facing text of sweep available in English and Russian, with English as the default, system-language autodetection with an English fallback, a language picker in the TUI settings, and a `--lang` CLI flag.

**Architecture:** A new `internal/i18n` package holds two compiled-in catalogs (`catalog_en.go` as the source of truth, `catalog_ru.go` as its translation) behind `i18n.T(key, args...)`. The active language is one atomic package-level value, set once per process before commands are built; every string that leaves the program becomes a `T` call. A new `internal/settings` package owns a small `settings.yaml` living next to `config.yaml`. System language arrives through a new `UILanguage()` method on the existing `platform.System` interface.

**Tech Stack:** Go 1.27, `golang.org/x/sys/windows` (already a dependency) for `GetUserDefaultUILanguage`, cobra, bubbletea/lipgloss. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-28-i18n-design.md`

## Global Constraints

- Default language is English. Nothing renders differently until the user picks Russian or the system is Russian.
- Chain of precedence, highest first: `--lang` flag → `settings.yaml` next to `config.yaml` → system language → English.
- `--lang` accepts exactly `en` and `ru`. Any other value is a usage error, exit code 2.
- A whole run started with `--json` speaks English, whatever the chain says. The JSON answer must be byte-identical for `en` and `ru`.
- Codes never translate: `status`, `action`, `kind`, `id`, `profile`, `reason`-as-code, registry notes `needs_admin`, log action names (`removed`, `trashed`, `failed`, `skipped`, `pending`, `ran`, `registry_delete`, `registry_failed`, `registry_skipped`, `registry_planned`).
- Rule data never translates: `name`, `description`, `category`, `id` in YAML.
- `T` never returns an empty string for a missing key: active language → English → the key itself.
- `settings.yaml` sits in the directory of the resolved `--config`. Without the flag that directory is `%APPDATA%\sweep`.
- No new module dependencies. `gofmt`, `go vet ./...`, `golangci-lint run` stay clean. Tests never call `t.Parallel()`.
- Every task keeps `go test ./... -count=1` green and commits its own work.

## Review Focus

Five things the spec implies that most plausibly break, each pinned to the task that owns it:

1. **A `--json` run under a Russian interface.** A user runs `sweep scan --json` on a Russian system; a parser expecting `"reason": "in_use"` must still match. Forced English has to apply before any scanning builds a message, not only at print time. Pinned in Task 3 (early force in `langEarly`) and Task 10 (byte-equality test).
2. **A key with no Russian entry.** A translator misses a line; the screen must show English, never blank. Pinned in Task 1 (`TestMissingKeyFallsBackToEnglish`).
3. **Switching language without a restart.** The user picks Русский on the settings screen; the very same screen and every other screen re-render in Russian, and the choice survives a relaunch. Pinned in Task 4 (`TestLanguageChoiceRendersInRussian`, `TestLanguageChoiceSurvivesRelaunch`).
4. **Elevation drops the language.** The registry flow restarts as administrator; the child process must keep the chosen language. Pinned in Task 4 (`TestRestartForwardsLang`).
5. **A bad `--lang` value.** `sweep --lang de scan` must exit 2 with a usage message, not silently fall back to English. Pinned in Task 3 (`TestUnknownLangIsAUsageError`).
