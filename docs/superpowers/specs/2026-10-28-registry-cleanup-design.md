# Чистка реестра — узкий безопасный набор

Дата: 2026-10-28. Статус: дизайн на проверке.

## Зачем

`sweep` чистит файлы по правилам. Пользователи ждут от чистильщика и работы с
реестром, но «чистильщики реестра» в стиле CCleaner удаляют безвредные записи
и иногда ломают программы. Эта функция добавляет только те категории, где
польза понятна, а риск низкий.

Цель — не «найти побольше», а **не навредить**: каждая находка объясняется,
каждое удаление требует подтверждения и резервной копии.

## Границы

**Входит в набор:**

1. Записи `Uninstall`, чья команда удаления указывает на несуществующий файл.
2. Значения автозапуска `Run`, чья программа не существует.
3. Подключи `App Paths`, чей путь по умолчанию не существует.

**Не входит (осознанно):**

- COM/CLSID, `SharedDLLs`, расширения файлов и ассоциации.
- Службы, политики, `HKLM\SYSTEM`, `SAM`, `SECURITY`, `Classes`.
- MUI cache, иконки, шрифты, справка — косметика без пользы.
- MSI-записи (`WindowsInstaller=1`) и обновления (`ParentKeyName`,
  `ReleaseType`): их удаление ломает удаление и обновление программ.
- Автоматический выбор находок. По умолчанию не отмечено ничего.

**Против цели:** «ускорить Windows». Функция только убирает заведомо мёртвые
записи и не обещает прироста скорости.

## Проверки

### 1. Uninstall

Ветки:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*
HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\*
```

Кандидат — подключ, у которого одновременно:

- есть `DisplayName`;
- нет `SystemComponent=1`, `ParentKeyName`, `ReleaseType`, `WindowsInstaller=1`;
- `UninstallString` (или `QuietUninstallString`) начинается с абсолютного
  пути, и этого файла нет.

Причина в отчёте: `uninstall command not found: <path>`. Подключи с
вложенными ключами не удаляются — только показываются с пометкой `has
subkeys`.

Путь с отключённого съёмного или сетевого диска не считается мёртвым:
находка пропускается с причиной `not_local`. Диск может вернуться, а запись
— остаться рабочей.

Разбор команды: снимаются кавычки; если путь записан без кавычек и содержит
пробелы, берётся самый длинный префикс, который существует как файл (так же
поступает `CreateProcess`). Мёртвой запись считается, только если не
существует ни один подходящий префикс с расширением.

### 2. Run

Ветки:

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Run
```

Проверяется каждое значение (кроме `(Default)`). Команда разбирается так:
снимаются кавычки, раскрываются `%ПЕРЕМЕННЫЕ%`, берётся первый токен. Если
путь абсолютный и файла нет — значение мёртвое. Если переменная не
раскрылась — пропуск с причиной `unknown variable`, а не удаление.

Переменные раскрываются и в `UninstallString`, и в значении по умолчанию
`App Paths`; правило `unknown variable` там то же.

Удаляется **значение**, не ключ `Run`.

### 3. App Paths

Ветки:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\*
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\App Paths\*
HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\*
```

Кандидат — подключ, чьё значение по умолчанию — абсолютный путь, которого
нет. Подключи с вложенными ключами показываются, но не удаляются.

## Защита

Отдельный `registry.Guard` разрешает работу только внутри трёх
перечисленных родительских веток. Всё остальное — отказ, даже если правило
или флаг просит. Дополнительные запреты:

- ключи с `SystemComponent=1` не удаляются;
- MSI и обновления не удаляются;
- ключ с вложенными ключами не удаляется;
- `HKLM` требует прав администратора; без них находки помечаются `[A]` и
  пропускаются с причиной `needs_admin`.

Представление реестра: `HKLM` читается через `KEY_WOW64_64KEY`, а
`WOW6432Node` — как литеральный путь, без двойного перечисления. `reg.exe`
вызывается 64-битный. Флаги `SystemComponent` и `WindowsInstaller` читаются
как DWORD `1` или строка `"1"`; `ParentKeyName` и `ReleaseType` — по факту
наличия значения.

## Резервная копия

Перед первым удалением создаётся каталог:

```
%LOCALAPPDATA%\sweep\registry-backups\YYYYMMDD-HHMMSS\
```

Для каждой находки — файл `.reg`, снятый `reg.exe export <key> <file> /y`
(для значения `Run` — экспорт родительского ключа один раз). Рядом
`manifest.json`: находка → файл копии.

**Правило без исключений:** если экспорт не удался, удаление этой находки не
выполняется. Отчёт называет причину.

Порядок операции: сначала все нужные экспорты, затем `manifest.json`, затем
первое удаление. Перед каждым удалением проверка «нет подключей» повторяется:
снимок «до» успевает устареть. Совпавший до секунды каталог получает суффикс.
`--dry-run` не пишет копий и каталогов. Чистки старых копий в v1 нет.

## Команды

```
sweep registry scan [--json]
sweep registry clean [--dry-run] [--yes] [--json]
```

`scan` только читает. Таблица: KIND, NAME, KEY, REASON, ADMIN. JSON — один
документ `schema: 1` с массивом находок.

`clean` сначала печатает план, затем требует `--yes` (или ответ в
терминале). Без терминала и без `--yes` — код 3, как у `clean`. Коды 0/1/2/4
те же. `--dry-run` показывает, что было бы удалено, и не пишет копий.

По умолчанию `clean` не удаляет ничего, пока пользователь не выберет
находки: в CLI выбор задаётся `--select <kind:key[:value]>`; без `--select`
команда отказывается работать и просит выбрать. TUI даёт галочки.

Разбор `--select`: `kind` — `uninstall`, `run` или `apppath`; ключ — полный
путь; `value` допустим только у `run`; значение отделяется последним
двоеточием; сравнение без учёта регистра. Неизвестный `kind` — код 2.
`--dry-run` работает без `--select` и показывает все находки как
невыбранные.

JSON: `scan` печатает `{schema: 1, findings: [...]}`, где находка несёт
`kind, name, key, value, path, reason, admin, has_subkeys`. `clean --json`
печатает один документ результата с `backup_dir`, а не два документа подряд.

## TUI

На стартовом экране появляется кнопка `Registry cleanup`. Экраны повторяют
поток файловой чистки:

```
Registry scan -> Review (галочки, причины) -> Confirm (сколько ключей,
куда пойдёт .reg) -> Cleaning -> Done (удалено, пропущено, путь копий)
```

- Находки с `[A]` выбираются; если процесс не повышен, экран предлагает
  перезапуск и передаёт выбор новому процессу скрытым флагом
  `--preselect-registry`.
- По умолчанию не отмечено ничего.
- Кнопка «Select safe only» отсутствует: безопасных «по умолчанию» здесь
  нет.

Шаги экранов: `scan` — 1, `review` — 2, `confirm` — 3, `cleaning` — 4,
`done` без номера. `--preselect` остаётся за файловыми правилами.

Журнал: `rule` пуст, `path` — ключ (для значения `run` — `ключ\значение`),
действия `registry_delete`, `registry_skip`, `registry_failed`.

## Устройство

| Пакет | Ответственность |
| --- | --- |
| `internal/platform` | интерфейс `Registry` и windows/fake реализации: перечисление, чтение значений, удаление значения/ключа, экспорт |
| `internal/registry` | находки, детекторы, guard, план, резервные копии, исполнитель |
| `internal/cli` | команды `registry scan/clean`, JSON-документ |
| `internal/tui` | экраны реестра, переиспользуют рамку и кнопки |
| `internal/report` | запись в тот же JSONL-журнал: `action: registry_delete` |

`internal/registry` не знает про CLI и TUI; оба получают один `Plan` и один
`Result`.

## Тесты

- Детекторы на фейковом реестре: мёртвый путь, живой путь, путь на съёмном
  диске (`not_local`), MSI, обновление, `SystemComponent`, неизвестная
  переменная, значение с кавычками и с пробелами.
- Guard: отказ вне трёх веток, отказ на ключ с вложенными ключами.
- Исполнитель: экспорт вызывается до удаления; неудачный экспорт
  останавливает находку; `needs_admin` без прав.
- CLI: `scan` ничего не меняет; `clean` без `--select` — ошибка; без
  терминала и `--yes` — код 3.
- Интеграционный тест только при `SWEEP_REGISTRY_INTEGRATION=1`: создаёт
  `HKCU\Software\sweep-test`, прогоняет экспорт, удаление и восстановление,
  затем убирает за собой.
- Проверка на этой машине: только `scan`, без удалений.

## Мои решения (проверить при чтении)

- Отдельная команда, а не `kind: registry` в YAML: набор узкий и
  курируемый, правила сообщества здесь опаснее пользы.
- Удаление значения `Run`, а не ключа.
- MSI, обновления и `SystemComponent` не трогаем.
- Без `--select` `clean` не делает ничего: осознанный выбор важнее удобства.
- Экспорт через `reg.exe`: системный инструмент, формат `.reg` открывается
  двойным щелчком, восстановление понятно пользователю.
- Путь на съёмном или сетевом диске считается живым: пропуск `not_local`.
- `[A]`-находки выбираются и переживают перезапуск с правами через
  `--preselect-registry`.
- Спека остаётся описанием v1, где реестра нет; расширение фиксируется в
  `docs/decisions.md` и README, а не переписывает спеку задним числом.

## Открытые вопросы

Ответы владельца от 2026-10-28:

- `[A]` отмечать и перезапускать с сохранением выбора — да.
- Интеграционный тест на `HKCU\Software\sweep-test` под флагом — да.
- Съёмные и сетевые диски — пропускать с `not_local`.

Других открытых вопросов нет; остальное — дело исполнителя.
