# Дизайн мультиязычности

Дата: 2026-10-28. Статус: утверждён.

## Зачем

`sweep` сегодня говорит только по-английски. Для пользователя, который
чистит диск на русской Windows, это лишний барьер: кнопки, подсказки и
причины находок приходится переводить в голове. Задача — дать выбор
языка, оставив английский по умолчанию.

Второй язык сейчас только русский. Механизм строится так, чтобы
добавить третий язык означало дописать один файл каталога, а не трогать
код.

## Цели

1. Видимые тексты на двух языках: английский и русский.
2. Английский — по умолчанию. Ни одна строка не меняется, пока язык не
   выбран.
3. Автоопределение от языка Windows с fallback на английский.
4. Выбор языка в настройках TUI, сохраняется между запусками.
5. Флаг `--lang` для CLI-команд.
6. Технические идентификаторы (`--json`, логи, ключи правил) остаются
   английскими.

## Не-цели и анти-цели

**Не-цели:**

- Не переводятся данные правил: `name`, `description`, `category`, `id` в
  YAML. Это файлы, которые пользователь читает и пишет руками; ломать их
  сменой языка нельзя.
- Не создаётся система загрузки переводов из внешних файлов (.po, .json).
  Каталоги компилируются в бинарник.
- Не переводятся README и docs. Они остаются английскими, русские разделы
  в `docs/decisions.md` — отдельная традиция проекта.
- Не добавляется язык, отличный от `en`/`ru`.

**Анти-цели — что было бы провалом:**

- Перевод значений в `--json` и в JSONL-логе. На них могут завязаться
  скрипты и парсеры; смена языка не должна менять структуру ответа.
- Падение или пустая строка там, где нет перевода. Отсутствующий ключ
  обязан вернуть английский текст, а не исчезнуть.
- Слом раскладки рамки из-за более длинных русских строк.

## Ограничения

1. Тесты проекта не используют `t.Parallel()`. Это проверено по кодовой
   базе. Глобальный переключатель языка поэтому безопасен для `-race`.
   Если в будущем добавят `t.Parallel()`, тесты, меняющие язык, должны
   остаться последовательными.
2. `config.yaml` — файл только для чтения: в TUI на нём нет печати,
   `rules.SaveConfig` не существует, подпись на экране «Effective config»
   гласит «Edit it in a text editor». Новая настройка не должна ломать
   этот контракт.
3. `golang.org/x/sys` и `golang.org/x/text` уже в зависимостях. Новых
   зависимостей не добавляем.
4. Фрейм меряет и режет строки через `lipgloss.Width` и руны (`fit` в
   `internal/tui/theme.go`), разбивает по словам (`wrapText`). Кириллица
   в терминале однобайтовая по ширине, ломать раскладку ей нечему.
5. `layout_test.go` проверяет, что каждая строка кадра шириной
   `width-1`. Переводы обязаны укладываться.

## Решения

### 1. Цепочка выбора языка

```
--lang  >  settings.yaml (TUI)  >  язык системы  >  английский
```

- `--lang` принимает `en` и `ru`. Неизвестное значение — ошибка
  использования, код выхода 2.
- Язык системы читает `platform.System.UILanguage()`. На Windows это
  `windows.GetUserDefaultUILanguage()`: старший байт `0x19`
  (`0x0419` = русский) даёт `ru`, всё остальное — `en`. На не-Windows
  всегда `en`.

Причина такого порядка: явное согласие пользователя (флаг или сохранённая
настройка) сильнее автоматики, а автоматика сильнее заглушки.

### 2. Пакет `internal/i18n`

Особенности:

- `type Lang string` с константами `LangEN` и `LangRU`.
- `func Use(lang Lang)` ставит активный язык, `func Current() Lang`
  отдаёт его. Хранение — через `atomic`, чтобы `-race` остался чистым.
- `func T(key string, args ...any) string` — главная точка вызова.
  Порядок поиска: активный язык → английский → сам ключ. Возврат ключа
  вместо пустой строки нужен, чтобы пропуск перевода был виден на экране,
  а не прятался.
- Подстановка — через `fmt.Sprintf`, если в тексте есть `%`.
- Каталоги лежат в двух файлах: `catalog_en.go` и `catalog_ru.go`. Оба —
  `map[string]string`. Английский каталог — источник истины, русский —
  его перевод.
- Ключ — точка с именем области и смысла: `tui.profile.start`,
  `cli.scan.header`, `registry.note.drive`, `guard.err.protected`.
- `func Missing() []string` отдаёт ключи, которых нет в активном
  ненулевом каталоге. Нужен тесту полноты.

Почему глобальный вызов, а не переводчик через зависимости: иначе
пришлось бы протаскивать функцию через `guard`, `scan`, `registry`,
`rules`, `report` и их опции — около десяти пакетов ради ~65 строк. Проект
и так держит состояние в одном месте на запуск; i18n — уместное
исключение в духе `golang.org/x/text/message`.

### 3. Как переводятся тексты ядра

Ядро больше не строит готовые английские строки там, где строка уходит
наружу. Вместо `fmt.Sprintf("...")` оно вызывает `i18n.T(key, args...)`.

Что считается «наружу» и подлежит переводу:

- `Set.Warnings` из `internal/rules` → stderr.
- `Skip.Detail` и warning из `internal/scan` → таблица и отчёт.
- `note()` и `Finding.Reason` из `internal/registry` → таблица, TUI, JSON.
  Переводится человекочитаемая часть; коды (`needs_admin`) остаются.
- `Entry.Note` из `internal/registry/clean.go`.
- `Message` и `refuse` из `internal/guard`.
- Тексты ошибок `internal/rules` в формате `file:line:col: msg`. Префикс
  с позицией остаётся английским и техническим, переводится только
  сообщение.
- JSON-ошибки JSON-схемы в `internal/rules/validate.go` уже идут через
  `message.NewPrinter(language.English)`. Точка подмены готова: печататель
  собирается по активному языку.

**JSON всегда по-английски.** Свободный текст в `--json` —
`findings[].reason` у реестра и `skipped[].detail` у пропущенных путей —
переводом не проходит. В кодовых путях `--json` перед сборкой сообщений
ставится `i18n.Use(LangEN)`; это решение заказчика, чтобы вывод для
скриптов оставался одинаковым при любом выборе языка. CLI однопоточен,
глобальная подмена здесь безопасна. Коды (`status`, `action`, `kind`,
`id`, `reason` как код) не переводятся никогда.

Где язык выставляется: один раз в `cmd/sweep/main.go` до построения
команд, и в `TestMain` тех пакетов, чьи тесты проверяют перевод.

### 4. Настройка в TUI и её хранение

Новый файл `settings.yaml`, лежащий **рядом с `config.yaml`**:

```yaml
language: ru
```

Путь — каталог разрешённого `--config`. Без флага это
`%APPDATA%\sweep`, с флагом `--config D:\x\config.yaml` — каталог
`D:\x`. Решение заказчика: настройка едет вместе с файлом правил, чтобы
портативный запуск сохранял язык.

Почему отдельный файл, а не `config.yaml`:

1. `config.yaml` объявлен read-only, у него нет `SaveConfig`. Запись туда
   сломала бы этот контракт и потребовала бы YAML-писателя, сохраняющего
   комментарии пользователя.
2. `config.yaml` валидируется списком `configFields`; новое поле
   пришлось бы добавлять в валидацию, которая кидает ошибку на
   неизвестные поля.
3. `settings.yaml` маленький, его пишет только TUI, и расширять его
   впоследствии безопасно.

Проводка: `deps` и `tui.Deps` получают `SettingsPath string`, который
ранний резолв языка уже вычислил (см. раздел 5) и кладёт рядом с
`config.yaml`.

Экран: в «Rules & settings» появляется пункт «Language», открывающий
новый `screenLang`. На нём две кнопки — English и Русский. Выбор пишет
`settings.yaml` и переключает язык немедленно: все экраны перерисовываются
по-русски без перезапуска. Под выбором — строка, что настройка сохранена.

### 5. Флаг `--lang`

Persistent-флаг root-команды.

Проблема: `Short` и `Long` у cobra задаются при построении команд, а
флаг парсится позже, в `Execute()`. Решение: в `NewRootCmd`, перед
построением подкоманд, язык резолвится ранним чтением `os.Args` на
предмет `--lang` и `--lang=ru`. Сам флаг объявляется в cobra как обычно —
для `--help` и для валидации.

Тот же ранний резолв читает `settings.yaml` (лёгкий разбор одного ключа)
и язык системы, чтобы у CLI-команд цепочка приоритетов была полной.
Дублирующее чтение `settings.yaml` допустимо: файл крошечный, а
`loadSet` вызовется как раньше.

`--lang` пробрасывается в дочерний процесс при запуске от
администратора: `restartParamsWith` в `internal/cli/restart_windows.go`
дополняется этим флагом. Приоритет цепочки не меняется — forwarded-флаг
сильнее свежей записи в `settings.yaml`.

### 6. Что остаётся английским

Согласовано с заказчиком:

- Всё в `--json`: `schema`, `reason`, `status`, `action`, `kind`, `id`,
  `profile`, а также свободный текст в `reason` и `detail` — принудительным
  английским из раздела 3.
- Имена действий в JSONL-логе: `removed`, `trashed`, `failed`, `skipped`,
  `pending`, `ran`, `registry_delete`, `registry_failed`,
  `registry_skipped`, `registry_planned`.
- `name`, `description`, `category`, `id` правил в YAML.
- Ключи реестра, пути, имена файлов.
- Коды выхода и их числа.
- Примеры команд в README.

### 7. Кириллица в рамке

`fit()` уже меряет через `lipgloss.Width` и режет по рунам, `wrapText`
разбивает по словам — кириллица работает без изменений.

Требование к переводам: держать длину близкой к английской. В колоночных
экранах (таблица правил, таблица реестра) использовать тот же `fit(name,
N)` с тем же `N`. Если перевод всё же длиннее, рамка обрежет его по
ширине: текст укоротится, раскладка не сломается.

### 8. Тесты

- `internal/i18n/catalog_test.go`:
  - каждый ключ русского каталога существует в английском;
  - русский каталог полон — тест падает, если появился английский текст
    без перевода;
  - каждый ключ английского каталога встречается в коде (защита от
    осиротевших ключей).
- Существующие тесты TUI и CLI остаются английскими и не меняются — по
  умолчанию язык `en`.
- Новые тесты: `i18n.Use(LangRU)` → конкретные экраны содержат русские
  фразы. Проверить профиль, подтверждение, реестр и ошибку CLI.
- Тест автоопределения — через фейковый `platform.System`.
- Тест цепочки приоритетов: `--lang` бьёт `settings.yaml`, тот бьёт
  систему.
