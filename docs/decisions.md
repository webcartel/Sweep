# Решения

Журнал решений, принятых при реализации `sweep`. Спека — источник истины
(`docs/sweep-spec.md`); всё, что в ней не описано и не покрыто её таблицей
«Открытые вопросы и решения по умолчанию», записывается здесь.

| Дата | Решение | Почему | Цена ошибки |
| --- | --- | --- | --- |
| 2026-10-17 | Модуль и репозиторий: `github.com/webcartel/sweep` | Репозиторий владельца уже создан на GitHub (пустой); в спеке стояла заглушка `github.com/<owner>/sweep` | Массовая замена импортов во всех пакетах |
| 2026-10-17 | Лицензия MIT, `Copyright (c) 2026 webcartel` | Решение по умолчанию из спеки | Смена лицензии после публикации правил сообщества |
| 2026-10-17 | Корень репозитория — каталог проекта (`Cleaner`), дерево из спеки — от него | В каталоге уже живут `AGENTS.md` и `docs/sweep-spec.md`; лишний уровень вложенности ничего не даёт | Имя каталога не совпадает с именем репозитория `sweep` — косметика |
| 2026-10-17 | README и код — по-английски, `docs/decisions.md` и спека — по-русски | Репозиторий публичный, в v1 интерфейс и имена правил английские; рабочие документы ведутся по-русски | Перевод README, если владелец захочет русский |
| 2026-10-17 | Версия по умолчанию `dev`, инжектится `-ldflags "-X github.com/webcartel/sweep/internal/cli.Version=..."` | Позволяет `goreleaser` проставлять версию, а тестам — свою | Правка одной строки в `.goreleaser.yml` на этапе релиза |
| 2026-10-17 | Файла `.golangci.yml` на этапе 0 нет: CI использует набор линтеров по умолчанию | Полный набор линтеров спеки — вопрос этапа 1+, когда появится код, который стоит ограничивать | Сначала ослабленный линт: пропущенные замечания появятся позже |
| 2026-10-17 | `sweep` без аргументов печатает справку, а не открывает TUI | TUI — этап 5; справка честнее заглушки | Поведение изменится на этапе 5 — это и есть план спеки |
| 2026-10-17 | `schema/rule.schema.json`, содержимое `rules/*`, fuzz-прогон и релиз через `goreleaser` в этап 0 не входят | Спека относит их к этапам 1, 6 и к разделу «Тестирование и CI» в целом | Ничего: критерий «Этап 0» из спеки выполнен полностью |
| 2026-10-17 | Каталоги `rules/{browsers,system,dev,apps}`, `schema`, `testdata` держатся в git через `.gitkeep` | Пустые каталоги git не хранит, а структура из спеки должна быть видна | Ничего |

| 2026-10-17 | YAML-парсер: `go.yaml.in/yaml/v3` v3.0.5 | Спека просит проверить на старте: `gopkg.in/yaml.v3` остановился на v3.0.1 (2022), поддерживаемый форк — `go.yaml.in/yaml/v3`; его же тянет golangci-lint, так что модуль уже проверен живым инструментом | Замена импорта и строки в `go.mod` |
| 2026-10-17 | `mode` по умолчанию — `contents` | В спеке умолчание для `mode` не названо (в отличие от `kind`). Во встроенных правилах каталоги-кэши — `%LOCALAPPDATA%\CrashDumps`, `SoftwareDistribution\Download`, `%LOCALAPPDATA%\pnpm\store`, `%USERPROFILE%\.gradle\caches` — перечислены без `mode`, то есть по смыслу чистится их содержимое | Правило без `mode` удалит не то: содержимое каталога вместо самого объекта (или наоборот) |
| 2026-10-17 | `min_size`: суффиксы `B/KB/MB/GB/TB` — степени 1024 | Спека пишет только «строка вида `50MB`»; 1024 совпадает с тем, как Проводник показывает размеры, и с ожиданием автора правила | Порог отбора файлов разойдётся с ожиданием автора правила |
| 2026-10-17 | `rules.Error` (`файл:строка:столбец`) заведён в этапе 1 вместе с загрузчиком | Загрузчик — первый, кто обязан назвать место: `min_size: 50XB` — ошибка формата, её нельзя прочитать и отложить до валидации | Ничего: тот же тип переиспользуют проверка схемы и смысловые проверки |

## Открытые мелочи после этапа 0

Ревью этапа 0 (коммиты `2bb192b..e644c63`) не нашло критичных замечаний. Исправлено по итогам ревью: пин версии линтера в CI (`v2.15.0` вместо `latest`) и разделение stdout/stderr в тестах `internal/cli` — тест не мог отличить вывод версии в правильный поток от вывода в stderr.

Осознанно отложено:

| Мелочь | Почему отложена |
| --- | --- |
| `sweep --help` обещает TUI, `scan` и `clean` в настоящем времени, хотя их ещё нет | Косметика текста; поведение появится на этапах 3–5, тогда справка станет правдой |
| Ветка `unknown` в `revision()` не покрыта тестом | Требует вынести поиск `vcs.revision` в чистую функцию — отдельная мелкая правка |
| Любая ошибка даёт код возврата 1, спека отводит 2/3/4 | Маппинг заводится вместе с командами, которым он нужен (этапы 1–4) |
| Дефолтная команда cobra `completion` в таблице команд спеки отсутствует | Стандартное поведение cobra, выключается одной строкой |
| Линт можно вынести в отдельную джобу и запускать параллельно тестам | Оптимизация времени CI, спека этого не требует |
| Первый прогон CI не наблюдался ни разу | `push` в этапе 0 не делался: локальные `gofmt`/`go vet`/`go test`/`golangci-lint` зелёные, но `windows-latest` и `ubuntu-latest` проверяются только после первого `push` |
