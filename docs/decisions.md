# Решения

Журнал решений, принятых при реализации `sweep`. Спека — источник истины
(`docs/sweep-spec.md`); всё, что в ней не описано и не покрыто её таблицей
«Открытые вопросы и решения по умолчанию», записывается здесь.

| Дата | Решение | Почему | Цена ошибки |
| --- | --- | --- | --- |
| 2026-10-17 | Модуль и репозиторий: `github.com/webcartel/sweep` | Репозиторий владельца уже создан на GitHub (пустой); в спеке стояла заглушка `github.com/<owner>/sweep` | Массовая замена импортов во всех пакетах |
| 2026-10-17 | Лицензия MIT, `Copyright (c) 2026 webcartel` | Решение по умолчанию из спеки | Смена лицензии после публикации правил сообщества |
| 2026-10-17 | Корень репозитория — каталог проекта (`Cleaner`), дерево из спеки — от него | В каталоге уже живут `AGENTS.md` и `docs/sweep-spec.md`; лишний уровень вложенности ничего не даёт | Имя каталога не совпадает с именем репозитория `sweep` — косметика |
| 2026-10-17 | README и код — по-английски, `docs/decisions.md` и спека — по-русски | Репозиторий публичный, в v1 интерфейс и имена правил английские; рабочие документы ведутся по-русски | Перевод README, если владелец захочет русский |
| 2026-10-17 | Версия по умолчанию `dev`, инжектится `-ldflags "-X github.com/webcartel/sweep/internal/cli.Version=..."` | Позволяет `goreleaser` проставлять версию, а тестам — свою | Правка одной строки в `.goreleaser.yml` на этапе релиза |
| 2026-10-17 | Файла `.golangci.yml` на этапе 0 нет: CI использует набор линтеров по умолчанию | Полный набор линтеров спеки — вопрос этапа 1+, когда появится код, который стоит ограничивать | Сначала ослабленный линт: пропущенные замечания появятся позже |
| 2026-10-17 | `sweep` без аргументов печатает справку, а не открывает TUI | TUI — этап 5; справка честнее заглушки | Поведение изменится на этапе 5 — это и есть план спеки |
| 2026-10-17 | `schema/rule.schema.json`, содержимое `rules/*`, fuzz-прогон и релиз через `goreleaser` в этап 0 не входят | Спека относит их к этапам 1, 6 и к разделу «Тестирование и CI» в целом | Ничего: критерий «Этап 0» из спеки выполнен полностью |
| 2026-10-17 | Каталоги `rules/{browsers,system,dev,apps}`, `schema`, `testdata` держатся в git через `.gitkeep` | Пустые каталоги git не хранит, а структура из спеки должна быть видна | Ничего |
| 2026-10-17 | YAML-парсер: `go.yaml.in/yaml/v3` v3.0.5 | Спека просит проверить на старте: `gopkg.in/yaml.v3` остановился на v3.0.1 (2022), поддерживаемый форк — `go.yaml.in/yaml/v3`; его же тянет golangci-lint, так что модуль уже проверен живым инструментом | Замена импорта и строки в `go.mod` |
| 2026-10-17 | `mode` по умолчанию — `contents` | В спеке умолчание для `mode` не названо (в отличие от `kind`). Во встроенных правилах каталоги-кэши — `%LOCALAPPDATA%\CrashDumps`, `SoftwareDistribution\Download`, `%LOCALAPPDATA%\pnpm\store`, `%USERPROFILE%\.gradle\caches` — перечислены без `mode`, то есть по смыслу чистится их содержимое | Правило без `mode` удалит не то: содержимое каталога вместо самого объекта (или наоборот) |
| 2026-10-17 | `min_size`: суффиксы `B/KB/MB/GB/TB` — степени 1024 | Спека пишет только «строка вида `50MB`»; 1024 совпадает с тем, как Проводник показывает размеры, и с ожиданием автора правила | Порог отбора файлов разойдётся с ожиданием автора правила |
| 2026-10-17 | `rules.Error` (`файл:строка:столбец`) заведён в этапе 1 вместе с загрузчиком | Загрузчик — первый, кто обязан назвать место: `min_size: 50XB` — ошибка формата, её нельзя прочитать и отложить до валидации | Ничего: тот же тип переиспользуют проверка схемы и смысловые проверки |
| 2026-10-17 | Схема формата — JSON Schema draft 2020-12 с `additionalProperties: false` на каждом уровне и `minItems: 1` у `targets` | Спека требует «неизвестные поля — ошибка»; целевой список из нуля целей — правило, которое ничего не делает молча, а ошибка честнее | Правило с `targets: []` станет ошибкой там, где автор ожидал «ничего не делать» |
| 2026-10-17 | Пакеты-носители `schema` и `rules` в корне репозитория | `go:embed` не берёт файл из родительского каталога, а спека фиксирует пути `schema/rule.schema.json` и `rules/...`; альтернатива — дублировать файлы | Два маленьких публичных пакета вместо правила «всё в `internal`» |
| 2026-10-17 | Сообщения схемы берутся у `jsonschema/v6`, `golang.org/x/text` становится прямой зависимостью | Библиотека отдаёт готовый текст только через локализованный принтер; свои сообщения на каждый вид ошибки — дублировать её словарь | Ещё одна прямая зависимость; замена на свои сообщения — один файл |
| 2026-10-17 | Неизвестные поля сообщаются по одному на поле, позиция — сам ключ; находки сортируются по позиции | Библиотека перечисляет все лишние поля одного маппинга одним сообщением и в порядке, который не совпадает с порядком в файле | Вывод отличается от «как у библиотеки», зато правка файла идёт по одной подсказке за раз, а порядок вывода предсказуем |
| 2026-10-17 | Согласованность `kind` с `path`/`cmd`/`args` — смысловая проверка этапа 1, а не схема | В таблице целей спеки обязательности полей нет, а сообщения `not` и `false schema` у библиотеки нечитаемы («'not' failed»); свои формулировки лучше | Проверка живёт в смысловом шаге, а не в схеме, и её не увидят редакторы по `$schema` |
| 2026-10-17 | Язык масок живёт в `platform`: `CompileMask` переводит маску в регулярное выражение; разделитель — разделитель, а не escape; метасимволы — `*`, `**`, `?` | Спека задаёт маску как путь Windows с `*`, `**` и `?`. `path.Match` трактует `\` как escape, поэтому путь, записанный как в таблице встроенных правил спеки (`...\User Data\*\`), не компилировался, а `\*` молча значил литеральную звёздочку (нашло ревью этапа 1). Ни один из трёх метасимволов не встречается в именах Windows, поэтому маске не нужен escape и грамматика остаётся однозначной. Проверка и обход файловой системы (`platform.Glob` этапа 2) берут компилятор из одного места | В грамматике спеки компилируется любая непустая маска, так что проверка ловит только пустую; символьные классы (`[a-z]`) не поддерживаются — `[` остаётся литералом |
| 2026-10-17 | `platform.Env` и `OSEnv` лежат в `internal/platform` без build-тега | Спека держит под тегом `windows` только WinAPI (`FS`, `Procs`, корзина); `os.LookupEnv` отвечает на тот же вопрос на любой платформе, а тесты `internal/rules` идут и на ubuntu-CI | Ничего |
| 2026-10-17 | Конфиг (`rules/config.go`) не имеет JSON Schema: разбирается руками теми же помощниками, что и правила (`field`, `errorAt`), и сам проверяет форму значений | Спека задаёт поля конфига строчкой текста, схемы у него нет; ручной разбор даёт те же позиционные сообщения, что и у правил, и не тянет вторую схему ради четырёх полей | Каждое новое поле требует и чтения, и проверки формы руками; забытая проверка тихо пропустит значение |
| 2026-10-17 | `profile.DefaultOnly` — только для встроенных профилей: в профиле из конфига ключ `default_only` отвергается как неизвестное поле | Спека перечисляет поля профиля закрытым списком (`include`, `include_tags`, `include_categories`, `max_risk`, `exclude`), а `DefaultOnly` не выражается ими — он нужен встроенным `default` и `dev` | Пользователь не может написать профиль «встроенный default плюс мои маски»; обходной путь — перечислить маски в `include` |
| 2026-10-17 | `rules.Set` несёт поле `Toggles map[string]model.RuleToggle` (в плане было `{Rules, Profiles, Warnings}`) | Выключатель конфига действует поперёк профилей: `enabled: false` убирает правило, о котором профиль молчит, а `enabled: true` возвращает то, что профиль не выбрал. `Select(set, имя)` конфига не видит, поэтому переключатели едут в наборе | Ещё одно поле в наборе и обязанность `Select` его учитывать |
| 2026-10-17 | `id`, повторённый в одном источнике, — ошибка; тот же `id` из более позднего источника — замена с предупреждением | Спека говорит и то («`id` не повторяется внутри источника», строка 132), и другое («правило с тем же `id` из более позднего источника заменяет предыдущее целиком», строка 127). Внутри источника ни один файл не главнее другого, между источниками порядок задан | Два файла в `%APPDATA%\sweep\rules` с одним `id` останавливают запуск — придётся убрать дубль вручную |
| 2026-10-17 | Отсутствующий `--rules-dir` — ошибка, отсутствующий пользовательский каталог — нет | Пользовательский каталог пуст на чистой машине, и это норма; каталог, названный флагом, назван осознанно, и молча его терять нельзя | Правило из опечатанного пути не подхватится без сообщения (только по флагу) |
| 2026-10-17 | `Toggles` с чужим `id` и профиль из конфига с именем встроенного дают предупреждение, а не ошибку | Конфиг может опережать правила (правило появится позже) или намеренно менять встроенный профиль; предупреждение видно, но не мешает работать | Шум в предупреждениях, если конфиг ведёт список выключенных правил «на будущее» |
| 2026-10-17 | Порядок в `rules.Select`: `exclude` перекрывает всё, выключатель конфига перекрывает профиль, `max_risk` применяется последним | Одно правило, которое надо выключить в профиле, должно выключаться даже при `enabled: true` в конфиге; а `max_risk` — предохранитель, и переключатель не должен его пробивать | Правило с `enabled: true`, попавшее под маску `exclude` профиля, не появится; маска профиля, которая не компилируется, даёт предупреждение и не выбирает ничего |
| 2026-10-17 | Объявлены коды возврата 0/1/2; коды 3 (нужно подтверждение без терминала) и 4 (частично) ждут своих команд | Спека перечисляет четыре кода, но у 3 и 4 пока нет потребителя: их возвращают `clean` и исполнитель этапов 4–5. `cli.ExitError` заводится здесь, потому что кодом 2 заканчиваются ошибки флагов, конфига и правил | Маппинг остальных кодов добавится вместе с командами, которые их возвращают |
| 2026-10-17 | `--config` и `--rules-dir` — постоянные флаги корня, а `--profile`, `--json`, `--category` объявлены у команды `list` | Спека даёт `--config`/`--rules-dir` всем командам, а `--profile`/`--json` — `scan`, `clean`, `list`; из них существует только `list`. Флаг, который команда молча игнорирует, хуже, чем объявить его второй раз, когда появится `scan` | При появлении `scan`/`clean` флаги переедут в постоянные, а `list` их унаследует |
| 2026-10-17 | Синтаксис `%ПЕРЕМЕННЫХ%` и их раскрытие живут в `platform` (`EnvNames`, `Expand`), и в имени допускаются скобки | Синтаксис нужен двум местам: смысловая проверка ищет неизвестные переменные, а `rules show` раскрывает их для отладки путей. Windows сам заводит `%ProgramFiles(x86)%`, и без скобок такая переменная молча осталась бы текстом | Раскрытие не понимает `%VAR:~1,2%`-подстановок cmd — если понадобятся, это отдельная работа |
| 2026-10-17 | Пустая маска в `include`/`exclude` — ошибка смыслового прохода; пустой `path` оставлен схеме (`minLength: 1`) | Ревью этапа 1 спросило, что значит пустая маска: она не берёт ничего и молчит об этом, а пустой путь уже отвергает схема — два прохода на один дефект дали бы две находки на одном месте | Файл правил, намеренно написавший пустую маску, будет отвергнут |
| 2026-10-17 | `rules validate` отдаёт находки ошибкой команды: cobra печатает их в stderr один раз, stdout остаётся пустым | Находки с позициями — диагностика, как у компилятора или `go vet`, и место ей в stderr; печать их самим и возврат той же строки ошибкой дублировала бы каждый текст, а «отчёт» в stdout мешал бы читать stdout как ответ команды | Скрипт, читающий stdout, у `rules validate` не увидит ничего — и находки, и предупреждения идут в stderr |

| 2026-10-18 | `golang.org/x/sys` v0.49.0 — прямая зависимость | `GetLongPathName`, `GetDriveType`, `MoveFileEx`, ленивая загрузка `SHFileOperationW` из `shell32` и снимок Toolhelp есть только здесь; `syscall` отдаёт их частично и без обёрток UTF-16 | Строка в `go.mod` и в зависимостях релиза; замена на `syscall` — один файл, но с потерей части вызовов |
| 2026-10-18 | `FS` расширен `LongPath`, `DriveType` и полем `Info.Link` | Спека требует `GetLongPathName`/`GetDriveType` (583) и разбора junction (335), но в её списке методов `FS` их нет. Один фейк вместо трёх интерфейсов; ядро по-прежнему на интерфейсах | Фейк и Windows-реализация выросли на три члена |
| 2026-10-18 | Обход маски — портируемая функция `platform.GlobPaths(fs, mask)`; её зовут и настоящая ФС, и фейк | Одна семантика glob и для кода, и для тестов (как решено с `CompileMask`); `Mask.Match` остаётся фильтром истины | Расхождение поведения можно увидеть только в тестах, а не в одном месте кода |
| 2026-10-18 | `GlobPaths` строит кандидатов по структуре сегментов и на выходе отсеивает их через `Mask.Match` + `Lstat`; в reparse points не заходит | Комментарий `CompileMask` прямо отдаёт превращение `**` в обход вызывающему; фильтр в конце снимает расхождения на смешанных сегментах (`b**`) | Промежуточные кандидаты не проверяются маской целиком — лишняя работа на больших деревьях (см. «Осознанно отложено») |
| 2026-10-18 | `platform.NewFS()` и `platform.NewProcs()`: под windows — настоящие, иначе `ErrNotWindows` | CLI и сканер должны компилироваться и на ubuntu | Вызов на Linux — ошибка времени выполнения, а не компиляции |
| 2026-10-18 | `guard.New(fs, env, cwd, excludePaths)` — `cwd` для относительных путей | Внутри `guard` нет `os.Getwd` (спека 324); тесты детерминированы | Вызывающий обязан передать рабочий каталог |
| 2026-10-18 | Корень диска распознаётся синтаксически (`X:\`), без перечисления дисков; так же ловятся `$Recycle.Bin`, `System Volume Information`, `EFI` и `Recovery` на каждом корне | Не нужен `GetLogicalDrives`; UNC и съёмные диски ловит проверка типа диска | Путь через том без буквы (`\\?\Volume{...}`) отвергается как «не фиксированный диск», хотя мог быть диском C: |
| 2026-10-18 | Любой отказ `guard` — `model.ReasonProtected` с текстом в `Verdict.Message`; `not_found` остаётся делом сканера | Спека (353) называет причину защиты `protected`; `model.SkipReason` получает значения из 221 | Причины разных отказов различаются только текстом |
| 2026-10-18 | `mode: files` на корнях и на данных пользователя разрешён только с непустым `include` **и** `min_age_days > 0` | Буквальное чтение строк 343 и 345: «`contents` и `self` без фильтров» — то есть защита снимается только фильтрами | Правило с одним фильтром из двух не пройдёт — это и есть страховка |
| 2026-10-18 | Диапазоны списка: «только сам путь» (корни), «путь и ниже» (поддеревья, данные пользователя, исключения Windows, `exclude_paths`) и «только внутри» (Program Files). Побеждает самое длинное совпадение, при равной длине — запрет. `%USERPROFILE%` — разрешающее исключение внутри запрещённого `C:\Users` | Механически объясняет все строки 341–346 и не сужает список: `exclude_paths` попадают в тот же механизм и только запрещают. Без профиля-исключения не пройдёт ни одно правило внутри профиля | Список нельзя расширить конфигом; «только внутри» у Program Files означает, что сам каталог отказывается лишь с фильтрами |
| 2026-10-18 | `%SystemRoot%`, `%ProgramFiles%`, `%ProgramData%`, `%APPDATA%`, `%LOCALAPPDATA%` — «только сам путь» плюс `files`-с-фильтрами, а не «и ниже» | Иначе блокируется встроенное правило `%SystemRoot%\MEMORY.DMP` (`mode: self`) и чистка `Prefetch`, которые спека называет безопасными | Каталоги внутри Windows, не названные явно, остаются доступными для `contents` — это и есть смысл списка |
| 2026-10-18 | `RemoveOnReboot` тестом не подтверждаем | Метод пишет в `PendingFileRenameOperations` на машине под тестом: побочный эффект на машине разработчика и CI. Поведение проверяет ручной чек-лист релиза (спека 549) | Непроверенная ветка откладывается до релизного прогона |
| 2026-10-18 | Корзина — `SHFileOperationW` с `FOF_ALLOWUNDO`; структуру объявляем в пакете, в `x/sys` её нет | `IFileOperation` — COM на десятки строк ради одного вызова | Своя структура и ленивая загрузка `shell32` вместо готовой обёртки |
| 2026-10-18 | `Procs.Running` — снимок Toolhelp (`CreateToolhelp32Snapshot`), сравнение имён без учёта регистра | Один системный вызов; `EnumProcesses` пришлось бы дополнять открытием процессов ради имени | Снимок всей таблицы процессов на каждый вызов |

| Код 4 | `skipped + failed > 0` после запуска: часть путей осталась, отчёт называет их |
| Лог | `%LOCALAPPDATA%\sweep\logs\YYYY-MM-DD.jsonl`, одна строка на операцию; лог открывается до первого удаления — неоткрывшийся лог → код 1 и «ничего не делали». Каталог лога для тестов — поле `cli.deps.LogDir` (продакшн берёт из env) |
| Подтверждение в терминале | `Continue? [y/N]`, согласие только на `y`/`Y`; не-терминал без `--yes` → код 3 |
| `fake.FS` потокобезопасен | Мьютекс на каждой операции; `LongPath` рекурсивен — внутренняя рекурсия идёт через незахваченный метод (`longPath`), иначе дедлок. Нужен потому, что пул исполнителя читает и пишет карты одновременно |
| Устройство `\\?\` | `platform.devicePath` строится без `filepath.Abs`: Clean срезает завершающую точку — то, ради чего устройство и нужно. `Lstat`/`Remove` Windows-платформы откатываются к устройству для имён, которые Win32 «съедает» на хвосте |
| Порядок `PerRule` | В порядке плана; `Result.Files` одного правила — количество удалённых item-ов; `Skipped`/`Failed` правила суммируются в общий счётчик |

Принято после ревью этапа 4:

| Вопрос | Решение |
| --- | --- |
| Сбой `Procs.Running` | Новая причина `system_unknown`: список программ, которые нельзя прочитать, — это не «список пуст»; правило целиком пропускается, ошибка уходит `Warning`-ом на stderr |
| План перед вопросом | `clean` печатает план (таблицу или `--json`) до вопроса/кода 3: подтверждение не вслепую |
| Ctrl+C во время чистки | Поток дожидается, `clean interrupted` в stderr, код 0; что успело удалиться — видно из событий/лога |
| Успешная команда | Новое `CommandRan`-событие + строка лога `ran`/`ok` (у провала — `ItemFailed`, как было) |
| `RuleFinished` | Шлётся после завершения каждого правила (кроме снятого пользователем) |
| Dry-run и код 4 | Dry-run никогда не завершается кодом 4: удалять нечего, «остаться» некому, пречины печатаются и живут в отчёте |
| `summary` | Поля спеки `items`/`files`/`bytes_found` заполняются из поиска; `pending_reboot[]` не опускается (`[]`) |
| errno 145 | `in_use`, как записано выше; таблица errno и решение согласованы |

## Решения: переделка TUI под неопытного пользователя

| Вопрос | Решение |
| --- | --- |
| Рамка и шаги | Каждый экран — рамка на весь терминал, имя продукта и «Step N of 4»; тело, затем подсказка и кнопки. Это даёт постоянное место кнопкам и не даёт содержимому «прыгать» между экранами |
| Человеческие слова | Профили названы Everyday / Deep / Developer и объяснены строкой; риски — Safe / Careful / Risky; количество файлов с разрядами (`11,623`). Идентификаторы правил остаются на экране деталей |
| Пустые правила | Правила с нулём найденного скрыты: на этой машине 8 из 11 ничего не нашли, и список из «nothing» читается как шум. Строка «N rules found nothing here (click to show)» возвращает их; клавиша `E` делает то же |
| Мышь | Клик по строке выбирает правило, клик по `>` открывает детали, кнопки внизу — действия. Попадания считаются по геометрии последнего кадра (`clickBox`), а не по номеру строки, поэтому работают при любой ширине |
| ASCII-скин | В ASCII-режиме меняются все значки: `>`, `-`, `*`, `...`, `Up/Down`, `_`; рамка из `+ - |`. Раньше в консоли conhost выводились символы, которых там нет |
| Ширина и высота | Рамка рисуется шириной `terminal - 1` (иначе последняя граница переносится на новую строку) и высотой всего окна; тест `TestFrameFitsTheTerminal` держит обе границы |
| Опасные действия | Подтверждение повторяет сумму, говорит, куда уходят файлы (корзина или навсегда), и требует слово `yes` только при `DANGER`. Кнопка «Restart as administrator» появляется только когда правило её требует |
| Скан | Те же события ядра, но экран показывает полосу прогресса и общий найденный объём вместо карты правил |
| Что не делали | Настройку конфига и правил внутри TUI не добавляли — спека оставляет это CLI; горячие клавиши спеки сохранены. Дерево «категория → правило → items» заменено плоской таблицей и отдельным экраном деталей: на 26 правилах дерево только прячет строки, а детали на весь экран работают и на 80 колонках |
| Бейджи и числа | Риски пишутся словами спеки (`SAFE`/`MOD`/`DANGER`) и объясняются строкой-легендой; в таблице есть число файлов, как требует спека |
| Скан при запуске | Спека просит начинать скан сразу; оставлен стартовый экран с выбором глубины — неопытному пользователю нужен один понятный вопрос до работы. Отклонение осознанное: результат всё равно показывается до удаления |
